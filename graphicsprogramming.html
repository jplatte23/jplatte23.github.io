Rendering

C++ Ray Tracer

C++ graphics project focused on CPU ray tracing, Phong lighting, triangle and sphere intersections, shader-based OpenGL rendering, and spline-driven camera motion.

This project demonstrates the rendering and math fundamentals behind engine work: tracing rays through scene data, shading surfaces, building geometry buffers, and moving cameras through 3D space.

C++ | OpenGL | GLSL | Ray Tracing

What I Learned

  • Building geometry buffers directly from image data, spline samples, and parsed scene descriptions.
  • Connecting CPU-side geometry generation to OpenGL VAOs, VBOs, shader inputs, uniforms, and draw calls.
  • Using matrices, camera transforms, tangents, normals, and binormals to move through 3D space.
  • Writing GLSL shaders for height coloring, texture mapping, and Phong lighting.
  • Implementing ray-sphere and ray-triangle intersection tests from the underlying math.
  • Interpolating per-vertex surface data with barycentric coordinates for triangle shading.

Heightfield Rendering

I converted grayscale image data into 3D terrain geometry and rendered it through an OpenGL shader pipeline.

  • Sampled image pixels into height-based vertex positions.
  • Built separate VAO/VBO paths for point, wireframe, solid, and smoothed render modes.
  • Added keyboard switching between render modes during runtime.
  • Used shader uniforms for transform matrices, height scaling, exponent control, and render mode state.
  • Implemented a JetColorMap shader path for height-based terrain coloring.

02

Spline Track & Camera Motion

I used Catmull-Rom splines to generate a continuous track and drive a camera along the path.

  • Evaluated spline position and derivative using a Catmull-Rom basis matrix.
  • Computed tangent, normal, and binormal vectors along the path.
  • Generated rail cross-section geometry from the moving coordinate frame.
  • Moved the camera along the spline using LookAt with position, focus, and up vectors.
  • Loaded multiple spline files to create a longer generated path.

CPU ray tracing

03

CPU Ray Tracing

I implemented a scene-file ray tracer that casts primary rays through each pixel, intersects them against spheres and triangles, and shades the nearest hit.

  • Parsed scene data for triangles, spheres, lights, and ambient light.
  • Implemented ray-sphere intersection using the quadratic equation.
  • Implemented ray-triangle intersection with plane tests and barycentric inside checks.
  • Interpolated triangle normals, diffuse color, specular color, and shininess using barycentric weights.
  • Added first-pass shadow rays for light obstruction, with imperfect shadows noted in the project readme.

Interesting Challenges

Making Math Visible

The project pushed me to turn abstract graphics math into visible output: height values became terrain, spline derivatives became camera orientation, and barycentric weights became smooth triangle shading.

Debugging The Pipeline

Small mistakes in buffer layout, shader inputs, normal transforms, or intersection tests could break the whole image, so each feature needed to be isolated and verified visually before layering on the next system.
