Technical Project

Custom Game Engine

A from-scratch C++ engine project focused on real-time rendering, animation, collision, profiling, and multithreaded jobs.

This project grew from rendering a triangle into a small engine playground with textured meshes, lighting, materials, skeletal animation, inverse kinematics, collision tests, post-processing, and performance tooling.

C++ | HLSL | DirectX | Engine Architecture

What I Learned

  • Advanced graphics debugging through controlled scenes, shader isolation, and Visual Studio graphics tools.
  • Writing HLSL shaders for lighting, materials, normal maps, toon shading, rim lighting, skinning, and bloom.
  • Building reusable engine systems around assets, transforms, components, render objects, materials, and JSON scene data.
  • Implementing skeletal animation, bone transforms, skinned meshes, and FABRIK inverse kinematics.
  • Designing collision tests and unit tests for AABB and line segment intersection.
  • Profiling engine systems and visualizing multithreaded jobs with Chrome tracing.

01

Rendering Foundation

I built the base rendering path from primitives up: vertex buffers, index buffers, camera transforms, depth buffering, textured meshes, and reusable render objects.

  • Created vertex and index buffers for simple primitives.
  • Added camera and matrix transforms so objects could move through 3D space.
  • Implemented depth buffering so objects render correctly in front of and behind each other.
  • Loaded texture data and passed texture coordinates into shaders.
  • Wrapped repeated rendering setup into reusable helper classes.

02

Lighting, Materials & Shaders

I added material data, point lights, Phong lighting, toon shading, Lambert/Half-Lambert variants, rim lighting, and normal mapping to compare different lighting models in-engine.

  • Added a material class for properties like specular power and object color.
  • Implemented point lights and shader constants for lighting data.
  • Wrote Phong, Lambert, Half-Lambert, rim, and toon shading variants.
  • Added tangent input data and a normal map shader for surface detail.
  • Used small test scenes to visually compare each shader model.

03

Skeletal Animation & FABRIK IK

I implemented skeleton and bone transform data, animation playback, a skinned shader, and an unconstrained FABRIK IK pass with debug visualization for joint positions and rotations.

  • Created skeleton and bone transform classes for hierarchical animation data.
  • Used parent-child bone relationships to build final transform matrices.
  • Implemented animation playback over time using bone pose data.
  • Added a skinned shader to deform model vertices by bone matrices.
  • Built an unconstrained FABRIK IK pass with debug axes for joint verification.
Animation IK Algorithms

04

Collision & Unit Tests

I implemented a physics/collision layer using AABBs and line segments, then wrote unit tests for AABB-vs-AABB and AABB-vs-line segment intersection before using the system for platform collision.

  • Implemented AABB and line segment collision primitives.
  • Wrote unit tests for AABB-AABB and AABB-line segment intersections.
  • Added a collision component to the player character.
  • Used collision checks to support standing on platforms and falling when not grounded.
  • Separated collision behavior from rendering so tests could validate the math directly.

05

Profiling & Multithreaded Jobs

I added timers and profiler output for engine functions, exported timing data to text/JSON, visualized it with Chrome tracing, and implemented a job manager with worker threads for asynchronous work.

  • Added profiler timers around engine update and render functions.
  • Saved timing output to text and JSON files for later inspection.
  • Used Chrome tracing to visualize frame timing and job execution.
  • Implemented a job manager and worker threads for multithreaded work.
  • Profiled the system to compare where time was being spent per frame.

06

Post-Processing Bloom

I rendered the scene to an off-screen target, isolated bright pixels, downsampled to half and quarter targets, applied two-pass Gaussian blur, then recombined opaque and additive states for the final bloom effect.

  • Rendered the scene into an off-screen render target.
  • Isolated bright pixels into a separate bloom texture.
  • Downsampled to half and quarter-size render targets.
  • Applied a two-pass Gaussian blur with linear sampling.
  • Combined opaque and additive blend states into the final frame.

Interesting Challenges

Debugging Graphics Without Guessing

This project pushed me to debug rendering problems through controlled scenes, shader isolation, graphics debugging tools, and small visual tests instead of changing random constants until something looked right.

Keeping Systems Reusable

As the engine grew, shared classes for assets, materials, transforms, render objects, animations, and components became the difference between a set of demos and a coherent engine.
